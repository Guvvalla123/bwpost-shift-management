# SECTION 1: API ROUTES (Postman Reference)
###############################################################################

Base URL (local):    http://localhost:5500
Base URL (prod):     https://your-backend.onrender.com  (or your deployed URL)

Auth: Cookie-based. Login first; cookies (token, refreshToken) are sent automatically.
      For Postman: enable "Send cookies" in request settings, or use Bearer token
      if you extract it from the login response.

Query params: ?page=1&limit=10&search=...&status=upcoming|ongoing|completed|all

--- PUBLIC (NO AUTH) ---
GET  /                         Health check (plain text)
GET  /health                   Health + DB status (JSON)
GET  /api/manager/shifts/public   Upcoming shifts (no auth)

--- AUTH — /api/users ---
POST /api/users/register
  Body: { "username": "john", "email": "john@example.com", "password": "Pass123!@#" }
  Auth: None (rate limited)

POST /api/users/login
  Body: { "email": "john@example.com", "password": "Pass123!@#" }
  Auth: None (rate limited)
  Returns: Sets httpOnly cookies (token, refreshToken)

POST /api/users/logout
POST /api/users/refresh-token
GET  /api/users/me
PUT  /api/users/profile

--- POSTMAN TIPS ---
1. Create environment variable: baseUrl = http://localhost:5500
2. Login flow: POST {{baseUrl}}/api/users/login → cookies auto-stored
3. For cookie-less testing: copy "token" from login response, add header:
   Authorization: Bearer <token>
4. Dynamic IDs: save shiftId, employeeId from responses; use {{shiftId}} in URLs
5. 401? Call POST {{baseUrl}}/api/users/refresh-token first, then retry

# SECTION 3: SECURITY OVERVIEW
###############################################################################

ACTIVE PROTECTIONS:
1. Helmet.js — Security headers (X-Frame-Options, HSTS, CSP, etc.)
2. express-mongo-sanitize — NoSQL injection prevention
3. xss-clean — XSS sanitization
4. CSRF-style origin check — Validates Origin on mutations
5. CORS — Env-based allowed origins
6. Rate limiting — Global (prod) + auth-specific (10/15min)
7. HTTP-only cookies — JWT + refresh token
8. Refresh token rotation — New token on refresh
9. bcrypt — Password hashing
10. Joi validation — Input validation
11. Role-based authorization — Manager vs Employee
12. Ownership verification — Managers only manage own shifts
13. isValidImageUrl — SSRF prevention (Cloudinary/HTTPS only)
14. Regex escaping — ReDoS prevention in search
15. Secrets in .env — Never hardcoded
16. Body size limit — 10kb
17. Graceful shutdown — SIGTERM/SIGINT
18. DB retry logic — 5 retries, 3s delay

ATTACKS BLOCKED:
- SQL/NoSQL Injection, XSS, CSRF, Brute-force, Session hijacking,
  Privilege escalation, DDoS, Clickjacking, SSRF

FUTURE: Account lockout, 2FA, Audit logging, stricter CSP, per-user rate limit
